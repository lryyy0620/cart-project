> 本文档是"演示动线"，不是讲稿全文；讲稿要你自己写，这里给的是**证据和动作**。

## 一、先定调：这个项目在证明什么

一句话：**同一个系统里，购物车走 AP（可合并），结算走 CP（要互斥）——两条路径并存，
是因为"丢一次点击"和"重复扣一次款"的代价完全不同。**

三个必须让听众记住的结论：

1. 分区期间两端都能写，恢复后是**并集**而不是覆盖（OR-Set + 版本向量）。
2. 合并满足交换/结合/幂等，所以**重复、乱序、延迟都不改变最终结果**。
3. 结算不能用 CRDT，因为它的语义正好相反（要"只成交一次"）。

## 三、9 个 topic 的现场操作手册

前置：`python scripts/local.py start`，打开 http://127.0.0.1:8010

| # | topic | 怎么造（页面上的动作） | 预期看到 | 一句话结论 |
|---|---|---|---|---|
| 1 | 副本突然宕机 | r2 卡片「宕机」→ r1 加购 → 观察 → r2「恢复」 | r2 变灰、少了商品；恢复后一两秒补齐 | 少数派不阻塞写，反熵补历史 |
| 2 | 分区 + 重复三次 | 链路 `r1↔r3`、`r2↔r3`「断开」→ 两端各加同款 → 故障注入「重复份数=3」→ 恢复 | 两边各有一份；恢复后数量**相加**，不是三倍 | dot 幂等，重复投递无副作用 |
| 3 | 延迟 10 秒 + 乱序 | 故障注入「延迟=10000、乱序窗口=500」→ 两条链路各加一件 → 观察 ops 缓慢增长 | 很久才一致，但最终一致 | 墓碑与到达顺序无关，不复活不丢 |
| 4 | 重启丢内存 | r2 卡片「重启」 | 日志出现 `重启：从 WAL 恢复 N 条操作`，购物车不变 | 先落盘再回 ack |
| 5 | 迁移一半宕机 | 实验工具 → 目标 r3「清空目标」→「迁移 1 页后中断」→「继续迁移」→「恢复同步」 | 中断时只有部分数据；继续后与源一致 | 版本向量本身就是断点 |
| 6 | 单 key 50% 请求 | 实验工具 →「开始压测」200 次 / 50% | `写入 200 条… 热 key 当前数量 100，零冲突` | 每次 add 独立 dot，热点没有写冲突 |
| 7 | 两客户端同时 CAS | 客户端「结算」→ 再点「并发抢单」 | 第一次 200，第二次 409 版本冲突 | CAS 要求"先读版本再写"，并发必有一方失败 |
| 8 | 时钟倒退一分钟 | 实验工具 → 时钟 -60000 → 注入 → 在**该副本**加购 | 卡片底部红字：`若按时间戳覆盖 → 苹果×N`，比 CRDT 少 | 物理时钟会回拨，HLC 不会 |
| 9 | 磁盘成功但响应丢失 | 故障注入「响应丢失率=1.0」→ 加购 | 提示 504，然后自动用同一 `request_id` 重试成功，数量不加倍 | 幂等键在操作里，重启也能重建 |

**"看不到效果"的三个常见原因**

1. 反熵周期 0.5 秒——动作太快会看不清分叉，先点「断开」再写。
2. 响应丢失率设成 0.5 时是随机的，演示用 1.0 更稳定。
3. 迁移目标没「清空」，它本来就同步好了，迁移自然是 0 条。

**三个"能加分"的细节**（讲的时候主动说）：

- 墓碑最初写错了：只在本地已有的 add 上打墓碑，乱序时商品会复活，是性质测试抓出来的。

## 六、可能被追问的 12 个问题

| 问题 | 一句话答案 |
|---|---|
| 删掉版本比较代码会怎样 | 结算退化成无条件写 → 重复扣款；购物车侧退化成 LWW → 覆盖丢数据 |
| 写入成功表示几个节点保存 | 购物车 acks=1（本地 fsync 即返回）；结算要求主副本 + 多数派可达 |
| 哪段执行能让客户端读到旧值 | 读只读本地，不等反熵；分区期间或 0.5s 窗口内都是旧值 |
| quorum 从 2 改成 1 失去什么 | 失去"结算时能联系到多数派"的保险，可能两个主各成交一次 |
| 为什么不能只用物理时钟 | 会回拨（场景 8 演示），且只能给全序、无法表达因果 |
| 刚才失败请求的 happens-before | 两次结算都读到版本 v 且互不知情 → **并发**，所以只能在一个主副本上串行化 |
| 为什么购物车不用 CAS | 并发添加应该都保留，CAS 会让一方失败，体验差且没必要 |
| 为什么不直接上 Raft | 购物车不需要全序；Raft 会把可用性绑在多数派上，分区少数派就不能加购了 |
| 墓碑什么时候清理 | 因果稳定后（所有副本都见过这个删除）才能 GC，本项目没做，写在限制里 |
| 为什么不用 Redis 的 CRDT | 课程要求自己实现合并语义；Redis CRDT 是 LWW 型，本来就不满足需求 |
| 测试是不是摆拍 | 68 个自动化测试 + 9 个场景 + 性质测试跑随机历史，`pytest` 一条命令复现 |
| 延迟真的是 10 秒吗 | 默认压到 300ms 便于回归，`--slow` 跑真实的 10 秒 |
